# 一般讀者模擬器

## 任務定位

把作者需要反覆進行的「如果我是第一次看到這段文字，我會怎麼想」外部化。模擬的不是一個完整而真實的人格，而是一套可追蹤的閱讀程序：我讀到什麼、如何由前文走到後文、在哪裡開始不確定，以及哪些問題會妨礙理解或行動。

預設只執行「一般讀者模擬」。若使用者同時提供作者意圖卡，先完成不受意圖影響的讀者模擬，再以獨立第二階段產生「作者意圖—讀者理解對齊報告」。不要把兩階段混成一般摘要或直接重寫文章。

## 輸入與模式

接受下列輸入：

- 必要：文章、論證片段或其他要檢查的文字。
- 選填：讀者閱讀情境、目標讀者的明示背景、作者意圖卡、指定要觀察的段落或溝通目的。
- 選填：輸出模式。未指定時採「讀者模擬」；明確要求對齊時才採「讀者模擬＋對齊報告」。

若輸入是 PDF、DOC 或 DOCX，遵守工作區規則：先用 Python 將原檔轉成同目錄的純文字檔，再以純文字檔作為分析標的；不要直接以二進位檔內容推測。若輸入已是 Markdown、TXT 或對話中的文字，直接使用原文。

## 不可違反的隔離原則

- 第一階段只能看文章、使用者明示的閱讀情境，以及文章內提供的資訊。不要先讀作者辯護理由、編輯意見、參考答案或外部資料。
- 即使作者意圖卡已經提供，也要先暫時擱置；不可用它替文章補洞、替作者辯護或改寫讀者的實際理解。
- 以第一人稱記錄讀者狀態，但不要扮演誇張、無知或帶有固定個性的角色。一般讀者可以有一般常識，卻沒有作者的完整研究脈絡。
- 將「我從文字讀到的內容」與「我猜測作者可能想說的內容」分開。不得把讀者推測寫成文章已明示的事實。
- 不以外部知識判定文章實質正確與否。若問題需要專業資料才能判斷，標記為「僅靠本文無法確認」，而不是直接判錯。
- 不直接重寫全文。輸出診斷、理解證據、問題與作者待決定事項；除非使用者另行要求改稿。

## 第一階段：一般讀者模擬

### 1. 建立閱讀邊界

先說明本次模擬的讀者情境與已知背景。若使用者沒有提供，就採「第一次接觸本文、具一般閱讀能力、不了解作者研究背景」的設定。不要自行增加專業背景。

### 2. 切分真正需要追蹤的單位

依段落、標題或重要 statement 切分。合併只提供修辭或重複資訊的句子；對每個包含定義、主張、理由、因果、預測、比較、價值判斷或行動指示的單位留下閱讀紀錄。

### 3. 逐單位追蹤閱讀過程

對每個重要單位依序回答：

- 我從這段文字直接理解到什麼？
- 我把關鍵術語或概念理解成什麼？這是原文定義、一般語感，還是我的推測？
- 我如何從前一句或前一段走到這一句？把實際走出的路徑寫成 `A → B → C`，不要替缺失的中間步驟補成作者預期路徑。
- 哪裡讓我不確定、停頓、回頭重讀或產生兩種可能理解？
- 我可能把作者的意思理解成什麼不同的命題？
- 我會問作者什麼，才能繼續理解或採取下一步？
- 這個問題的影響是：核心意思誤解、無法完成下一步推理、無法行動、降低信任，或只是一般好奇？

### 4. 使用閱讀導向的論證檢查

不要把這一步做成專家審稿；只檢查讀者是否能沿著文字走通。特別留意：

- 主張、理由、證據與結論是否在讀者眼中有連接。
- A 到 B 是否突然跳躍，是否缺少讀者需要的中間步驟。
- 因果、預測、比較或量化詞是否依賴未說明的條件。
- 同一術語在前後文是否可能換了意思，或適用範圍是否悄悄改變。
- 事實描述、推論、價值判斷、政策選擇與行動指示是否容易被讀者混為一談。
- 讀者是否知道結論適用於誰、何時、在什麼限制下成立。

若發現缺口，先報告「讀者在哪裡無法順利往下走」及其原因，不要直接宣告作者的論證必然錯誤。

### 5. 產生讀者模擬報告

使用下列結構；若內容很短，可合併小節，但不可省略理解斷點：

```markdown
# 一般讀者閱讀模擬報告

## 1. 閱讀設定
- 讀者情境：
- 已知背景：

## 2. 整體理解
我目前把本文理解成：

## 3. 逐段閱讀紀錄
### [段落或 statement]
- 我讀到：
- 我推到：A → B → C
- 我不確定或停頓在：
- 我可能誤解成：
- 我會問作者：
- 影響：核心誤解／推理中斷／行動受阻／信任下降／一般好奇

## 4. 最重要的理解斷點
依對作者溝通目的的影響排序，合併重複問題。

## 5. 我可能採取的理解或行動
只在文章有明示或可合理推出時填寫；無法判斷就明確說明。

## 6. 需要作者判斷的問題
列出不能由讀者或 agent 自行決定的問題。
```

逐段紀錄不是逐句摘要。優先保留會影響理解、推理、行動或信任的問題；一般好奇可集中在末段或省略。

## 第二階段：作者意圖—讀者理解對齊

只有在使用者提供作者意圖卡，或明確要求以作者意圖進行比較時才執行。先完成並保留第一階段報告，再開始第二階段；若環境支援獨立 agent，優先讓另一個 agent 只負責整合。若無法啟動獨立 agent，至少在同一回合中以新的分析階段處理，且不得回頭修改讀者原始理解。

作者意圖卡格式見 [references/author-intent-card.md](research-skills/skills/general-reader-simulator/references/author-intent-card.md)，對齊報告格式與限制見 [references/alignment-report.md](research-skills/skills/general-reader-simulator/references/alignment-report.md)。

執行規則：

1. 比較作者「希望讀者知道、相信、決定或採取的行動」與讀者實際讀出的內容。
2. 只比較重要命題，不把所有讀者疑問都當成文章缺陷。
3. 對每個落差指出它從哪個文字轉折產生，以及對作者目的的影響。
4. 意圖卡沒有提供的內容標記為「作者意圖未提供，待作者確認」，不可自行補全。
5. 相同問題只保留一次；先合併同類問題，再按影響排序。
6. 對齊狀態只使用：一致、部分一致、理解偏離、尚未形成。
7. 不替作者選擇修改方案；把需要決策的事項改寫成清楚的作者確認問題。

對齊報告最多保留 3 個關鍵理解落差、5 列核心命題對照與 5 個作者確認問題。結論先行，次要的日期、編號或統計疑問只有在影響理解、信任或行動時才列入。

## 最終品質檢查

- 第一階段是否只使用文章與明示閱讀情境？
- 是否用讀者第一人稱留下理解證據，而非改寫文章？
- 是否明確分開「原文說了什麼」「我推測什麼」「我不知道什麼」？
- 是否指出具體的理解轉折，而非只說「不清楚」？
- 是否把一般讀者困惑、專業正確性問題與作者尚未決定的範圍分開？
- 若有第二階段，是否保留第一階段的獨立性、沒有替作者辯護、沒有虛構作者意圖？
- 是否刪除不影響主要理解的重複或枝節問題？
